# CLAUDE.md — oci-postgres

## What This Project Does

Deploys a private PostgreSQL DB System on OCI plus an Ubuntu pgweb VM in a
public subnet. The VM connects to PostgreSQL using the DB system's private FQDN,
loads the Pagila sample database on first boot, and exposes pgweb on port 80.

Single Terraform phase in `01-postgres/`. No modules, no workspaces.

## Commands

```bash
./apply.sh              # check env, terraform init + apply, then validate
./destroy.sh            # teardown all resources
./validate.sh           # poll pgweb URL until reachable, print summary
./get_password.sh       # print PostgreSQL + VM credentials from tfstate
./check_env.sh          # validate oci/terraform/jq in PATH + OCI CLI connectivity
```

## Architecture

```
VCN: 10.0.0.0/23
  ├── postgres-subnet (10.0.0.0/25) — private, NAT gateway
  │     └── oci_psql_db_system  (PostgreSQL 14, port 5432)
  │
  └── vm-subnet (10.0.1.0/25) — public, Internet Gateway
        └── oci_core_instance  (Ubuntu 24.04, pgweb, port 80)
                                   └── connects to PostgreSQL private FQDN
```

- **Region:** us-ashburn-1
- **PostgreSQL shape:** `PostgreSQL.VM.Standard.E4.Flex.2.32GB` (2 OCPUs, 32 GB RAM)
- **VM shape:** `VM.Standard.E4.Flex` (1 OCPU, 4 GB RAM)
- **PostgreSQL provisioning:** typically 10–20 minutes

## Auth Pattern

- `~/.oci/config` DEFAULT profile — no credentials in code
- `OCI_COMPARTMENT_ID` env var → `TF_VAR_compartment_ocid` in apply/destroy
- Falls back to tenancy OCID from `~/.oci/config` if env var is unset
- SSH key generated by Terraform (ECDSA P-256), written to `01-postgres/keys/Private_Key`

## Secrets / Passwords

OCI Vault is not used. Passwords are `random_password` resources exposed as
sensitive Terraform outputs in `tfstate`. Retrieve with `./get_password.sh`.

- `postgres_password` — PostgreSQL admin (`postgres`) password
- `vm_password` — Ubuntu VM user (`ubuntu`) password; injected via cloud-init `chpasswd`

## Security Lists

| Subnet | Security List | Rules |
|--------|--------------|-------|
| postgres-subnet | `postgres-sl` | Ingress TCP 5432 from `10.0.1.0/25` only |
| vm-subnet | `postgres-vm-sl` | Ingress TCP 80 and TCP 22 from `0.0.0.0/0` |

Both lists allow unrestricted egress.

## Cloud-Init Quirks (baked into install_pgweb.sh.template)

1. **Network timing:** OCI fires cloud-init before internet routing is stable.
   Script loops on `curl -4 http://archive.ubuntu.com/` until reachable.
2. **apt lock race:** OCI boots cloud-init so fast that `apt-daily` grabs the
   apt lock first. Fix: retry loop on `apt-get update` with `pkill -9 -f apt`.
3. **IPv6 / IGW:** Force IPv4 for apt via `/etc/apt/apt.conf.d/99force-ipv4`.
4. **iptables catch-all REJECT:** OCI Ubuntu images have a catch-all iptables
   REJECT rule at INPUT position 5. Port 80 is not pre-allowed. Fix:
   `iptables -I INPUT 5 -p tcp --dport 80 -j ACCEPT`.

## pgweb Connection

pgweb does not pre-configure a connection — enter details manually in the browser:

| Field    | Value |
|----------|-------|
| Host     | `<postgres_private_ip>` (from `./get_password.sh`) |
| Port     | `5432` |
| Database | `pagila` |
| Username | `postgres` |
| Password | `<postgres_password>` (from `./get_password.sh`) |

## SSH to pgweb VM

```bash
ssh -i 01-postgres/keys/Private_Key -o StrictHostKeyChecking=no ubuntu@<pgweb_public_ip>
```

Logs: `/root/userdata.log` (cloud-init), `/root/db_load.log` (pagila load), `/root/pgweb.log` (pgweb service)
